## このページの考え方（毎回書き直さない）

**特定の公演日・公演名をこのページに書きません。** 公演の告知は Instagram・Facebook が正で、
このページはそこへ誘導し、お申し込みの方が**日付選択（カレンダー）で公演日を選んで**送ります。
公演が変わっても、このページも応答2も GAS も書き直さなくてよい形です。

**ご予約は「仮のお申し込み」で受けます。** 送信の時点では確定させず、
あゆな様がお席の状況を確かめて折り返しメールでご連絡し、そのご連絡をもって確定です。
ページにも自動返信にも「予約完了」の言い切りは書いていません。お代の案内も自動では送りません。

## 送信のしくみ

ファンクラブLPと**同じウェブアプリURL1本**へ送ります。行き先は、このフォームが送る
`form=reserve` を見て Apps Script 側が振り分けます（`28_本番フォーム_GAS_20260819.gs` の §ライブ予約）。

1件届くと次の3つが動きます。

1. 予約一覧「公式LINE ライブ予約一覧（紫あゆな）」に1行（公演日は `2026/09/20（日）` の形に整えて記録）
2. `Ayuna.8.mu@gmail.com` へ「○○様のお申し込み」のお知らせ（**仮のお申し込みである旨と、確定連絡のお願い入り**）
3. お申し込みくださった方へ、お預かりの自動返信（**確定はご連絡をもって**、と明記）

## 公開するときの順番（守らないと名簿が汚れます）

**GASを先に新しくしてから、このページを公開します。**

1. `Ayuna.8.mu@gmail.com` の Apps Script「紫あゆな 公式LINE フォームとファンクラブ受付」を開く
2. `28_本番フォーム_GAS_20260819.gs` の全文を貼り替える
3. `setupReserveReceiver` を実行 → 予約一覧ができ、当方へ編集者共有される
4. `testReserveReceiver` でメール2通を確かめる（テスト行はあとで消す）
5. **デプロイを管理 → 鉛筆 → バージョン=新バージョン → デプロイ**（URLは変わりません）
6. このリポジトリを上げて GitHub Pages を有効にする
7. 公開ページから1件送って、予約一覧・お知らせ・自動返信の3つを確かめ、テスト行を消す

古いバージョンのまま先に公開すると、`reserve` の振り分けが無いため、
**ファンクラブの名簿へ中身の欠けた行が入ります。**

## フォームが送る項目

`form`（`reserve` 固定）/ `showDate`（日付選択）/ `showNote` / `tickets` /
`name` / `kana` / `email` / `tel` / `source` / `message` / `submittedAt`

必須は `showDate` `tickets` `name` `kana` `email` `source` の6つです。
`showNote` `tel` `message` は任意にしてあります。

`source` は「このページをどちらでご覧になりましたか」の回答です（公式LINE ／ ホームページ ／ SNS ／ その他）。
公式LINEから `?from=line` を付けて開くと、公式LINEがあらかじめ選ばれた状態になります。

`website` という欄がHTMLにありますが、これは人に見えない位置に置いたボット除けです。
ここに文字が入っている送信は、機械によるものとして捨てています。

## 送信のしかた

`application/x-www-form-urlencoded` で送っています。独自のヘッダを付けないので、
ブラウザが送信前に別の問い合わせ通信（preflight）をせず、Apps Script の `e.parameter` でそのまま読めます。

お返事だけが読めなかったときのために、`mode: "no-cors"` でもう一度だけ送り直します。
そのとき `submittedAt` は最初と同じ値を送るので、受け側が同じお申し込みだと判断し、
予約一覧が2行に増えることはありません。
